# CLAUDE.md — agent Python

> Chargé seulement quand on travaille sous `agent/`. Les règles communes au projet sont dans `../CLAUDE.md`.

## Pièges

- **Ordre d'import dans `main.py`** : `install()` du patch multimodal doit précéder l'import des graphes. Le patch remplace l'attribut de module `ag_ui_langgraph.utils.convert_agui_multimodal_to_langchain` : après une montée de version d'`ag-ui-langgraph`, vérifier qu'un PDF attaché arrive encore au modèle (symptôme d'un patch devenu inopérant : l'agent ne « voit » aucun document).
- **`recursion_limit`** se règle dans `_AGENT_CONFIG` de `main.py` : un `.with_config()` sur le graphe est écrasé par la config qu'`ag_ui_langgraph` construit à chaque run.
- **Dashboard `/fixed`** : les bindings `{path}` de `src/a2ui/schemas/dashboard.json` (`/kpis/0..3/*`, `/trend`, `/share`, `/rows`, `/scope/*`…) doivent correspondre au data model écrit par `render_dashboard` (`src/fixed_agent.py`). Changer l'un sans l'autre donne des slots vides, sans erreur.
- **IDs de modèles et paramètres** (température, timeout, retries) vivent uniquement dans `src/models.py` ; les sites d'appel passent par `chat_model(...)`. Les noms affichés dans le chat sont dupliqués dans `../src/lib/agent-steps.ts` : changer un modèle ici, c'est aussi les changer là. IDs datés, jamais `-latest`. Tests : `uv run pytest` (le `conftest.py` pose une fausse `MISTRAL_API_KEY`, les modèles étant instanciés à l'import).
- **Répartition des modèles** : Ministral 3 3B pour l'agent principal et `query_pdf`, 8B pour `generate_a2ui`. Avec la clé actuelle (sondée le 2026-10-28), `mistral-small-2603` et `mistral-medium-2604` sont plafonnés à 0 requête/minute et `mistral-large-2512` renvoie un 403. L'agent principal en 8B n'a rien apporté à la mesure du 2026-10-28 (même latence). On monte **un rôle à la fois**, d'un cran (3B → 8B → 14B), et seulement sur preuve live. Le rendu est passé à 8B parce que, sur 3B, les questions de suivi renvoyaient des composants imbriqués, rejetés deux fois.
- **Appels d'outils streamés par `agent_chat_model`, sur le modèle de l'agent seulement.** Mistral envoie un appel d'outil en un seul chunk, qui porte aussi `finish_reason` ; `ag_ui_langgraph` écarte ce chunk et n'émet les arguments que sur un chunk suivant, donc rien n'était streamé et l'étape du chat n'apparaissait qu'une fois l'outil terminé. `_StreamingToolCallMistral` (`src/models.py`) redécoupe l'appel en début, arguments, fin. Ne pas l'appliquer au modèle de rendu (`_RENDER_MODEL`) ni à l'extracteur : l'appel interne `render_a2ui` serait streamé au client comme un appel d'outil orphelin. Tests : `tests/test_tool_call_streaming.py`.
- **`generate_a2ui` est `return_direct=True`** : le graphe s'arrête dès que la surface existe. Sans ce réglage, le 3B rappelait l'outil en boucle malgré le « STOP » du prompt (observé : 6 surfaces et 112 s pour une seule question). Garde-fou : `test_turn_ends_after_the_first_surface`. Le tour finit donc sur un `ToolMessage`, et Mistral accepte bien un message `user` après `tool` au tour suivant (vérifié en live).
- **`RENDER_EXAMPLE`** (`src/dynamic_agent.py`) est montré tel quel au modèle de rendu. Sans cet exemple de liste plate, le modèle invente `type` à la place de `component`, ou imbrique les objets. Il doit rester valide face à `validate_components`, ce que vérifie un test.
- **Typage (pyright, `uv run --with "pyright[nodejs]" pyright src tests` → 0 erreur)** :
  - `MistralErrorMiddleware` reste générique sur l'état. Lié à `AgentState`, il ne peut pas partager la liste `middleware` avec `CopilotKitMiddleware`, car le paramètre est invariant.
  - On écrit `ChatMistralAI(model_name=…)` : c'est l'alias du champ `model`, le seul nom que voit le typeur.
  - On lit le contenu d'un message via `.text` : `content` peut être une liste de blocs.
- **Hook httpx de CopilotKit** : `CopilotKitMiddleware` pose un hook de requête sur `model.client` et `model.async_client`. `ChatMistralAI` expose un `httpx.AsyncClient` brut, qui `await` chaque hook : avec `copilotkit` 0.1.90 (hook synchrone) tout appel async échouait en `TypeError: object NoneType can't be used in 'await' expression`. Corrigé en passant à `copilotkit` ≥ 0.1.93 (hook async pour `AsyncClient`) ; ne pas redescendre. Garde-fou : `tests/test_httpx_hook.py` (modèle Mistral réel sur `httpx.MockTransport`, hors réseau).
- **Erreurs Mistral** : `MistralErrorMiddleware` (`src/errors.py`) doit rester **après** `CopilotKitMiddleware` dans `middleware=[…]`. Le premier de la liste est le plus externe : placé après, il enveloppe l'appel au modèle au plus près et capte l'exception avant que le middleware CopilotKit ne la voie. Les erreurs des sous-LLM dans les outils reviennent en `ToolMessage` préfixé `MISTRAL_ERROR: ` ; `before_model` saute alors à la fin (`jump_to: end`) avec le message français, sans quoi le modèle rappellerait l'outil en boucle. Toute autre exception est relancée telle quelle.
- **`query_pdf` lit lui-même le dernier document joint** dans `runtime.state` (comme `generate_a2ui`) et ne prend que `question` : quand l'agent devait recopier le texte, il n'en passait que 1 à 6 % (mesure live du 2026-10-28). Plus aucune troncature côté serveur : le seul plafond est `PDF_TEXT_MAX_CHARS` (`src/lib/pdf.ts`). L'en-tête `[Document: …]` écrit par le middleware multimodal sert de repère à `latest_document_text` : le changer casse la lecture.
- **Mesure des latences et des tokens** : `cd agent && uv run python scripts/measure.py --dry-run` liste les tours sans appel réseau ; sans `--dry-run`, chaque tour consomme des tokens Mistral (**12 tours maximum par exécution**, `--repeat` et `--extra` inclus). Le plafond de texte est lu dans `PDF_TEXT_MAX_CHARS` de `src/lib/pdf.ts` (aucune seconde constante) ; `--agent-model`, `--extractor-model` et `--render-model` essaient un autre modèle sans toucher `src/models.py`.
- **Langue de sortie** : `FRENCH_OUTPUT_RULE` (`src/locale.py`, écrit en anglais) est injecté dans quatre prompts : `SYSTEM_PROMPT` de `fixed_agent.py` et de `dynamic_agent.py`, le prompt de `generate_a2ui`, et le message système de `query_pdf` (aussi celui d'`extract_dashboard_data`). Les chaînes que le modèle formate lui-même (valeur de KPI, delta, légende) suivent les conventions françaises (« 94 930 M€ », « +6,1 % ») et doivent rester lisibles par `parseAmount` / `autoDelta` (`../src/lib/format.ts`) : un séparateur isolé y est un séparateur décimal, donc jamais de virgule comme séparateur de milliers (« 1,234 » serait lu 1.234). Garde-fou : `tests/test_locale.py`.
