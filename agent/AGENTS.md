# CLAUDE.md — agent Python

> Chargé seulement quand on travaille sous `agent/`. Les règles communes au projet sont dans `../CLAUDE.md`.

## Pièges

- **Ordre d'import dans `main.py`** : `install()` du patch multimodal doit précéder l'import des graphes. Le patch remplace l'attribut de module `ag_ui_langgraph.utils.convert_agui_multimodal_to_langchain` : après une montée de version d'`ag-ui-langgraph`, vérifier qu'un PDF attaché arrive encore au modèle (symptôme d'un patch devenu inopérant : l'agent ne « voit » aucun document).
- **Pas de CORS, garde `Origin` dans `main.py`** : `reject_browser_requests` renvoie 403 dès qu'une requête porte un en-tête `Origin`, que les navigateurs envoient sur tout POST et que le runtime Next (`HttpAgent`, `fetch` de Node) n'envoie pas (sondé le 2026-10-29). Ne pas réintroduire `CORSMiddleware`, même restreint : un CORS n'empêche que la lecture de la réponse, et un POST `no-cors` avec un `Blob` sans type arrive sans `Content-Type`, donc FastAPI le parse en JSON et lance le graphe. `main()` écoute sur `127.0.0.1` (défaut d'uvicorn), comme `pnpm dev:agent`. Ce n'est pas une authentification : un processus local (curl, script) passe toujours. Garde-fou : `tests/test_main.py`.
- **`recursion_limit`** passe par `_AGENT_CONFIG` de `main.py` : un `.with_config()` sur le graphe est écrasé par la config qu'`ag_ui_langgraph` construit à chaque run. Sa valeur, `AGENT_RECURSION_LIMIT` (25, `src/models.py`), vient d'une mesure : tour normal de `/dynamic` 11 super-étapes, 4 de plus par appel d'outil supplémentaire (15, 19, 23 pour 2, 3, 4 `query_pdf`) ; les deux hooks qui s'exécutent une fois par tour (document manquant, réponse française à un outil en échec) ajoutent une étape chacun. 25 est le tour à quatre appels avec ces deux étapes. Le routage tient un tour à 11 ; la marge ne sert que si le fournisseur ignore `tool_choice`. Un dépassement coupe le flux sans `RUN_ERROR` ni message français. Garde-fou : `tests/test_turn_limits.py`, à revoir à chaque montée de `langchain`, `langgraph` ou `copilotkit`.
- **Dashboard `/fixed`** : les bindings `{path}` de `src/a2ui/schemas/dashboard.json` (`/kpis/0..3/*`, `/trend`, `/share`, `/rows`, `/scope/*`…) doivent correspondre au data model écrit par `render_dashboard` (`src/fixed_agent.py`). Changer l'un sans l'autre donne des slots vides, sans erreur. L'extracteur 8B remplit le tableau de bord par `extract_json` (`DASHBOARD_EXTRACTION_PROMPT`) ; `src/dashboard_checks.py` décide de ce qui arrive à l'écran (un nombre que le document n'écrit pas est retiré) et `_dashboard_components` retire du gabarit les blocs sans donnée (une grille a autant de colonnes que d'enfants). Sans KPI, tendance, répartition ni ligne exploitables, ou si l'extraction échoue, la surface est « Extraction impossible ».
- **IDs de modèles et paramètres** (température, timeout, retries) vivent uniquement dans `src/models.py` ; les sites d'appel passent par `chat_model(...)`, sauf les deux graphes d'agent, qui utilisent `agent_chat_model()` : même modèle, avec l'adaptateur de streaming des appels d'outils, sans lequel les étapes du chat apparaissent en retard. Les noms affichés dans le chat sont dupliqués dans `../src/lib/agent-steps.ts` : changer un modèle ici, c'est aussi les changer là. IDs datés, jamais `-latest`. Tests : `uv run pytest` (le `conftest.py` pose une fausse `MISTRAL_API_KEY`, les modèles étant instanciés à l'import).
- **Répartition des modèles** : Ministral 3 3B pour l'agent principal, 8B pour `query_pdf`, `generate_a2ui` et l'extracteur du tableau de bord `/fixed` (`render_dashboard`). L'extracteur est passé à 8B sur preuve live (lecture exacte des colonnes d'un tableau : 1 essai sur 4 en 3B, 4 sur 4 en 8B, même texte et même prompt). Avec la clé actuelle (sondée le 2026-10-28), `mistral-small-2603` et `mistral-medium-2604` sont plafonnés à 0 requête/minute et `mistral-large-2512` renvoie un 403. L'agent principal en 8B n'a rien apporté à la mesure du 2026-10-28 (même latence). On monte **un rôle à la fois**, d'un cran (3B → 8B → 14B), et seulement sur preuve live. Le rendu est passé à 8B parce que, sur 3B, les questions de suivi renvoyaient des composants imbriqués, rejetés deux fois.
- **Appels d'outils streamés par `agent_chat_model`, sur le modèle de l'agent seulement.** Mistral envoie un appel d'outil en un seul chunk, qui porte aussi `finish_reason` ; `ag_ui_langgraph` écarte ce chunk et n'émet les arguments que sur un chunk suivant, donc rien n'était streamé et l'étape du chat n'apparaissait qu'une fois l'outil terminé. `_StreamingToolCallMistral` (`src/models.py`) redécoupe l'appel en début, arguments, fin. `agent_chat_model` envoie aussi `parallel_tool_calls: false` : le 3B a déjà émis deux `generate_a2ui` dans un même message. Ne pas appliquer le redécoupage au modèle de rendu (`_RENDER_MODEL`) ni à l'extracteur : l'appel interne `render_a2ui` serait streamé au client comme un appel d'outil orphelin. Tests : `tests/test_tool_call_streaming.py`.
- **`generate_a2ui` est `return_direct=True`** : le graphe s'arrête dès que la surface existe. Sans ce réglage, le 3B rappelait l'outil en boucle malgré le « STOP » du prompt (observé : 6 surfaces et 112 s pour une seule question). Garde-fou : `test_turn_ends_after_the_first_surface`. `return_direct` n'arrête le graphe qu'après tout le lot d'appels du message : c'est `parallel_tool_calls: false` qui évite une double surface. Le tour finit donc sur un `ToolMessage`, et Mistral accepte bien un message `user` après `tool` au tour suivant (vérifié en live).
- **`RENDER_EXAMPLE`** (`src/dynamic_agent.py`) est montré tel quel au modèle de rendu. Sans cet exemple de liste plate, le modèle invente `type` à la place de `component`, ou imbrique les objets. Il doit rester valide face à `validate_components`, ce que vérifie un test.
- **Typage (pyright, `uv run --with "pyright[nodejs]" pyright src tests` → 0 erreur)** :
  - `MistralErrorMiddleware` reste générique sur l'état. Lié à `AgentState`, il ne peut pas partager la liste `middleware` avec `CopilotKitMiddleware`, car le paramètre est invariant.
  - On écrit `ChatMistralAI(model_name=…)` : c'est l'alias du champ `model`, le seul nom que voit le typeur.
  - On lit le contenu d'un message via `.text` : `content` peut être une liste de blocs.
- **Hook httpx de CopilotKit** : `CopilotKitMiddleware` pose un hook de requête sur `model.client` et `model.async_client`. `ChatMistralAI` expose un `httpx.AsyncClient` brut, qui `await` chaque hook : avec `copilotkit` 0.1.90 (hook synchrone) tout appel async échouait en `TypeError: object NoneType can't be used in 'await' expression`. Corrigé en passant à `copilotkit` ≥ 0.1.93 (hook async pour `AsyncClient`) ; ne pas redescendre. Garde-fou : `tests/test_httpx_hook.py` (modèle Mistral réel sur `httpx.MockTransport`, hors réseau).
- **Erreurs Mistral** : `MistralErrorMiddleware` (`src/errors.py`) doit rester **après** `CopilotKitMiddleware` dans `middleware=[…]`. Le premier de la liste est le plus externe : placé après, il enveloppe l'appel au modèle au plus près et capte l'exception avant que le middleware CopilotKit ne la voie. Les erreurs des sous-LLM dans les outils reviennent en `ToolMessage` préfixé `MISTRAL_ERROR: ` ; `before_model` saute alors à la fin (`jump_to: end`) avec le message français, sans quoi le modèle rappellerait l'outil en boucle. Toute autre exception est relancée telle quelle. Un outil `return_direct` termine le graphe sans passer par `before_model` : c'est alors `after_agent` qui ajoute le message français.
- **`query_pdf` lit lui-même le dernier document joint** dans `runtime.state` (comme `generate_a2ui`) et ne prend que `question` : quand l'agent devait recopier le texte, il n'en passait que 1 à 6 % (mesure live du 2026-10-28). L'outil est plafonné à `MAX_QUERY_PDF_CALLS_PER_TURN` (2) par tour, sans appel à l'extracteur au-delà, car chaque appel renvoie tout le document à Mistral. Deux plafonds de texte existent : `PDF_TEXT_MAX_CHARS` dans le navigateur (`src/lib/pdf.ts`) et `DOCUMENT_MAX_CHARS` (`src/multimodal_middleware.py`), un garde-fou par document juste au-dessus, contre un client qui contourne le navigateur, posé à la conversion pour couvrir aussi le modèle de l'agent. Un test impose que le second reste supérieur au premier. L'en-tête `[Document: …]` écrit par le middleware multimodal sert de repère à `latest_document_text` : le changer casse la lecture.
- **Le routage est imposé** par `PdfTurnRoutingMiddleware` (`src/routing.py`), sur les deux graphes, via `tool_choice` et une fonction `required_tool(messages)`. `/dynamic` : `query_pdf` puis `generate_a2ui`, à chaque tour. `/fixed` : `render_dashboard` au premier tour sur un document, puis le modèle est libre (réponse en chat ou nouveau rendu sur clic de puce). Laissé libre, le 3B renvoyait `""` au tour de suivi (écrit à cause de l'ancienne consigne « chaîne vide », ne pas la réintroduire), rappelait `query_pdf` en boucle, ou rendait une surface vide sans document. Sans document, il n'y a plus de branche `"none"` : `before_agent` termine le tour sur une phrase fixe (`NO_DOCUMENT_REPLY` de chaque graphe), sans appel au modèle. Cette phrase arrive dans le chat par `MESSAGES_SNAPSHOT`, sans événement `TEXT_MESSAGE_*`. Conséquence assumée sur `/dynamic` : tout message après un document, même « merci », relance les deux outils. `MAX_QUERY_PDF_CALLS_PER_TURN` reste, au cas où le fournisseur ignorerait le forçage.
- **`query_pdf` est la seule source de chiffres du rendu.** `generate_a2ui` passe l'historique par `without_document_text` : avec le texte brut, le modèle refabriquait une série depuis les graduations d'axes. Si l'extraction a échoué (`failed: true`, `extraction_failed`), il renvoie la surface de repli sans appeler le modèle. L'extracteur est sans flux (`disable_streaming=True`), sinon `ag_ui_langgraph` relaie son JSON brut dans le chat.
- **JSON invalide de l'extracteur, avec un bon contenu** : le 8B écrit `"value": 2,8` malgré la consigne, et de vrais sauts de ligne dans les chaînes sur une réponse narrative (6 essais sur 6). `_extraction_json` ne répare qu'après un échec du parsing strict : `strict=False` pour les sauts de ligne, et les virgules décimales hors des chaînes, jamais à 3 chiffres après la virgule (`94,930` peut être un séparateur de milliers) : un échec affiché vaut mieux qu'un chiffre faux. Le résultat réparé est réécrit en JSON standard, car `extraction_failed` et le repli le relisent strictement. `response_format` n'est pas utilisé par `query_pdf` (réponses narratives non mesurées) : en sonde sur 3B, `json_object` rendait des zéros. Sonde : `SETUP/2026-10-30-query-pdf-fixes/evidence/`.
- **Mémoire bornée en nombre de fils** : `BoundedMemorySaver` (`src/checkpoints.py`, 32 fils par graphe) évince le fil le moins récemment écrit. Un fil évincé repart d'un état vide, sans erreur. La croissance **au sein** d'un fil n'est pas bornée.
- **Mesure des latences et des tokens** : `cd agent && uv run python scripts/measure.py --dry-run` liste les tours sans appel réseau ; sans `--dry-run`, chaque tour consomme des tokens Mistral (**12 tours maximum par exécution**, `--repeat` et `--extra` inclus). Le plafond de texte est lu dans `PDF_TEXT_MAX_CHARS` de `src/lib/pdf.ts` (aucune seconde constante) ; `--agent-model`, `--extractor-model` et `--render-model` essaient un autre modèle sans toucher `src/models.py`.
- **Langue de sortie** : `FRENCH_OUTPUT_RULE` (`src/locale.py`, écrit en anglais) est injecté dans cinq prompts : `SYSTEM_PROMPT` de `fixed_agent.py` et de `dynamic_agent.py`, `DASHBOARD_EXTRACTION_PROMPT` de `fixed_agent.py`, le prompt de `generate_a2ui`, et le message système de `query_pdf`. Les chaînes que le modèle formate lui-même (valeur de KPI, delta, légende) suivent les conventions françaises (« 94 930 M€ », « +6,1 % »). Garde-fou : `tests/test_locale.py`.
- **Encodage des fichiers du projet** : toujours lire avec `encoding="utf-8"` (Windows ouvre en cp1252 par défaut). `copilotkit.a2ui.load_schema` ne le fait pas : `dashboard.json` s'affichait en « PÃ©RIMÃ¨TRE ». `fixed_agent.py` lit donc le schéma lui-même ; garde-fou : `tests/test_locale.py`.
- **Extraction du tableau de bord en mode JSON** : `render_dashboard` appelle `extract_json(..., json_mode=True)` (`response_format={"type": "json_object"}`), lui seul. Cause vue sur la puce `Consommation` : le 8B omet une virgule entre `"subtitle"` et `"kpis"` (2 essais sur 2). Mesure du correctif sur 8 appels : JSON exploitable 4 fois sur 4 avec le mode JSON et une valeur typée, 1 sur 4 avec le prompt typé seul.
- **Une `value` de `trend` ou de `share` doit être un nombre** : `_points` écarte tout le bloc si une valeur est une chaîne (`"0,4 %"`). Le `delta` d'un KPI ou d'une ligne n'est gardé que sur la ligne du document qui porte aussi sa valeur.
